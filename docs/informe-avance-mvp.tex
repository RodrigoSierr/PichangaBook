\section{Resumen del Avance del MVP}

En este informe presentamos las evidencias del Producto Mínimo Viable (MVP) de \textbf{PichangaBook Arequipa} (repositorio \texttt{github.com/RodrigoSierr/PichangaBook}). El proyecto resuelve tres problemas frecuentes en el alquiler de canchas sintéticas en Arequipa: las reservas duplicadas entre recepción y WhatsApp, la dificultad del organizador para cobrar las cuotas individuales de sus compañeros y la falta de suplentes verificados de último minuto. El monorepo cuenta con tres carpetas conectadas entre sí: \texttt{/backend-nestjs} (API REST y WebSockets en NestJS + PostgreSQL), \texttt{/web-admin-tailwind} (panel web omnicanal para dueños) y \texttt{/mobile-flutter} (pantallas en Flutter/Dart y cliente móvil ejecutable).

\section{Diagramas del Sistema}

\subsection{Diagrama de Arquitectura Backend--Frontend}

El sistema sigue una arquitectura cliente-servidor en tiempo real configurada en \texttt{src/app.module.ts}. Tanto el panel web de los dueños (\texttt{/web-admin-tailwind}) como la aplicación móvil de los organizadores (\texttt{/mobile-flutter}) se comunican con el servidor \textbf{NestJS} mediante endpoints REST (\texttt{/api/*}) y un canal persistente de \textbf{WebSockets (Socket.io)} gestionado por \texttt{BookingsGateway} y \texttt{RealtimeBus}. El backend consta de \texttt{AuthModule} (\texttt{AuthService} + \texttt{OtpService} + JWT), \texttt{ComplexesModule} (\texttt{ComplexesService} + \texttt{AvailabilityService}), \texttt{BookingsModule} (\texttt{BookingsService} + \texttt{BookingsGateway}), \texttt{SubstitutesModule}, \texttt{IntegrationsModule} (\texttt{CulqiService}, \texttt{MapsService}, \texttt{MediaService}) y \texttt{DatabaseModule} (PostgreSQL con \texttt{pg Pool} / \texttt{PGlite WASM}).

\subsection{Diagrama Entidad-Relación de la Base de Datos (PostgreSQL)}

El esquema relacional definido en \texttt{backend-nestjs/schema.sql} comprende \textbf{12 tablas} y la vista \texttt{v\_complex\_ratings}:
\begin{itemize}
  \item \texttt{districts} (\texttt{PK code}, \texttt{UQ name}, \texttt{lat}, \texttt{lng}, \texttt{is\_key\_zone}): catálogo de distritos de Arequipa (\texttt{CAYMA}, \texttt{YANAHUARA}, \texttt{CERRO\_COLORADO}, \texttt{JLBYR}, \texttt{SACHACA}, \texttt{MIRAFLORES}, \texttt{PAUCARPATA}, \texttt{CERCADO}).
  \item \texttt{users} (\texttt{PK id}, \texttt{full\_name}, \texttt{role}, \texttt{UQ phone\_e164}, \texttt{phone\_masked GENERATED}, \texttt{phone\_verified\_at}, \texttt{trust\_score}).
  \item \texttt{complexes} (\texttt{PK id}, \texttt{FK owner\_id -> users.id}, \texttt{FK district\_code -> districts.code}, \texttt{UQ ruc}, \texttt{verification\_status}, \texttt{lat}, \texttt{lng}).
  \item \texttt{courts} (\texttt{PK id}, \texttt{FK complex\_id -> complexes.id}, \texttt{name}, \texttt{surface}, \texttt{players\_per\_side}, \texttt{price\_per\_hour\_cents}, \texttt{open\_hour}, \texttt{close\_hour}).
  \item \texttt{bookings} (\texttt{PK id}, \texttt{FK court\_id -> courts.id}, \texttt{FK organizer\_id -> users.id}, \texttt{channel}, \texttt{status}, \texttt{payment\_mode}, \texttt{starts\_at}, \texttt{ends\_at}, con restricción \texttt{EXCLUDE USING gist} anti-solapamiento).
  \item \texttt{booking\_events} (\texttt{PK id BIGSERIAL}, \texttt{FK booking\_id -> bookings.id}, \texttt{FK complex\_id -> complexes.id}, \texttt{FK actor\_id -> users.id}, \texttt{event\_type}, \texttt{payload JSONB}).
  \item \texttt{reviews} (\texttt{PK id}, \texttt{FK complex\_id -> complexes.id}, \texttt{FK user\_id -> users.id}, \texttt{rating SMALLINT 1..5}, \texttt{comment}).
  \item \texttt{split\_payments} (\texttt{PK id}, \texttt{UQ,FK booking\_id -> bookings.id}, \texttt{FK organizer\_id -> users.id}, \texttt{total\_slots}, \texttt{paid\_slots}, \texttt{UQ share\_token}, \texttt{status}).
  \item \texttt{payment\_shares} (\texttt{PK id}, \texttt{FK split\_payment\_id -> split\_payments.id}, \texttt{FK payer\_user\_id -> users.id}, \texttt{payer\_name}, \texttt{method}, \texttt{UQ provider\_charge\_id}, \texttt{amount\_cents}).
  \item \texttt{substitute\_profiles} (\texttt{PK id}, \texttt{UQ,FK user\_id -> users.id}, \texttt{FK district\_code -> districts.code}, \texttt{position}, \texttt{punctuality\_score}, \texttt{clip\_url}, \texttt{clip\_duration\_s BETWEEN 15 AND 30}).
  \item \texttt{substitute\_invitations} (\texttt{PK id}, \texttt{FK substitute\_id -> substitute\_profiles.id}, \texttt{FK organizer\_id -> users.id}, \texttt{FK booking\_id -> bookings.id}, \texttt{status}).
  \item \texttt{contact\_relays} (\texttt{PK id}, \texttt{FK booking\_id -> bookings.id}, \texttt{FK user\_a\_id, user\_b\_id -> users.id}, \texttt{proxy\_number}) y \texttt{relay\_messages} (\texttt{PK id BIGSERIAL}, \texttt{FK relay\_id -> contact\_relays.id}, \texttt{FK sender\_id -> users.id}, \texttt{body}, \texttt{was\_redacted}).
\end{itemize}
